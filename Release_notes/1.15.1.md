[PnetCDF](https://parallel-netcdf.github.io) Version 1.15.1 Release Notes (September 18, 2026)
-------------------------------------

* Bug fixes
  + Fix a bug causing programs to hang when calling a blocking collective put
    API and one of the process has a zero-length request. The bug was reported
    in [Issue #238](https://github.com/Parallel-NetCDF/PnetCDF/issues/238).
    See fix in [PR #239](https://github.com/Parallel-NetCDF/PnetCDF/pull/239).
    Note this process hanging bug only happens when using collective put APIs,
    but not other APIs (i.e. nonblocking and independent APIs).
  + Fix a divide-by-zero error when opening a file that is using the Lustre
    Progressive File Layout (PFL). The bug was reported in
    [Issue #234](https://github.com/Parallel-NetCDF/PnetCDF/issues/234).
    See fix in [PR #236](https://github.com/Parallel-NetCDF/PnetCDF/pull/236).
  + Fix the detection of MPI base compiler names when PrgEnv-cray is loaded,
    where cc, CC, and ftn are wrappers of Cray clang and Cray Fortran
    compilers.
    See [PR #233](https://github.com/Parallel-NetCDF/PnetCDF/pull/233).
  + Fix utility program `pnetcdf_version` for printing the version string of
    base compiler of MPICC wrapper when the base is a classic Intel compiler.
    See [PR #232](https://github.com/Parallel-NetCDF/PnetCDF/pull/232).

* Build recipes
  + When using Intel oneAPI compilers to build PnetCDF, users may encounter
    errors at the link time. An ad hoc solution provided by NERSC Consulting
    and Support has been added to `doc/README.CRAY.md`.

* Other updates:
  + All man pages have been updated with string "Print date" being replaced
    with "Last modified date".
    See [PR #230](https://github.com/Parallel-NetCDF/PnetCDF/pull/230).

* New test programs
  + tst_zero_len_recvar.c and tst_zero_len_recvar2.c in folder test/testcases
    were added to test the bug reported in
    [Issue #238](https://github.com/Parallel-NetCDF/PnetCDF/issues/238).
  + test/Lustre contains programs for testing the bug found in
    [Issue #234](https://github.com/Parallel-NetCDF/PnetCDF/issues/234) and
    resolved in [PR #236](https://github.com/Parallel-NetCDF/PnetCDF/pull/236).
